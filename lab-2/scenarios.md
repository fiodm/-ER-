
# Лабораторна робота №2 — Gherkin-сценарії

## SC-01. Перегляд каталогу

**Вимоги:** REQ-01, REQ-02

```gherkin
Feature: Перегляд каталогу

Scenario: Перегляд товарів
  Given у базі даних існують товари з категоріями
  When користувач відкриває каталог
  Then система відображає назви та поточні ціни товарів

Scenario: Перегляд картки товару
  Given користувач переглядає каталог з товаром "Ноутбук"
  When користувач вибирає товар "Ноутбук"
  Then система відображає назву, ціну та категорію товару
```

## SC-02. Оформлення замовлення

**Вимоги:** REQ-03, REQ-04, REQ-09

```gherkin
Feature: Оформлення замовлення

Scenario: Успішне оформлення замовлення
  Given покупець вибрав два товари з кількістю 1 та 2
  And обидва товари існують у каталозі
  When покупець підтверджує замовлення
  Then система створює один Order і два OrderItem
  And зберігає кількість та unit_price кожної позиції

Scenario: Некоректна кількість товару
  Given покупець вибрав товар з кількістю 0
  When покупець підтверджує замовлення
  Then система показує помилку некоректної кількості
  And не створює Order та OrderItem

Scenario: Порожнє замовлення
  Given кошик покупця не містить жодного товару
  When покупець підтверджує замовлення
  Then система відхиляє оформлення з повідомленням "Кошик порожній"
  And не створює Order

Scenario: Історична ціна після зміни каталогу
  Given замовлення містить OrderItem з unit_price 500 грн
  And поточна ціна відповідного Product змінена на 600 грн
  When покупець переглядає своє замовлення
  Then система показує збережену ціну 500 грн
  And не змінює OrderItem.unit_price
```

## SC-03. Оплата замовлення — поглиблений UC

**Вимоги:** REQ-05, REQ-06

```gherkin
Feature: Оплата замовлення

Scenario: Ініціювання оплати
  Given покупець має Order зі статусом pending
  And сума позицій замовлення становить 1000 грн
  And для замовлення немає успішної оплати
  When покупець ініціює оплату
  Then система надсилає платіжному сервісу ідентифікатор замовлення та суму 1000 грн

Scenario: Успішне підтвердження оплати
  Given для Order зі статусом pending ініційовано платіж на 1000 грн
  And платіжний сервіс надіслав автентичне підтвердження успіху
  When система обробляє підтвердження платежу
  Then система створює або оновлює Payment зі статусом success
  And встановлює Order.status у paid
  And для замовлення існує не більше одного Payment

Scenario: Відмова платежу
  Given для Order зі статусом pending ініційовано платіж
  And платіжний сервіс надіслав автентичне повідомлення про відмову
  When система обробляє результат платежу
  Then система створює або оновлює Payment зі статусом failed
  And залишає Order.status рівним pending
  And повідомляє покупцю про невдалу оплату

Scenario: Повторне підтвердження платежу
  Given для замовлення вже існує Payment зі статусом success
  And платіжний сервіс повторно надіслав те саме підтвердження
  When система обробляє повторне підтвердження
  Then система залишає один запис Payment для цього Order
  And зберігає Order.status рівним paid

Scenario: Спроба повторно оплатити сплачене замовлення
  Given Order має статус paid
  And для нього існує Payment зі статусом success
  When покупець повторно ініціює оплату
  Then система відхиляє повторну оплату
  And не надсилає новий платіжний запит
```

## SC-04. Додавання товару

**Вимога:** REQ-07

```gherkin
Feature: Керування каталогом

Scenario: Адміністратор додає товар
  Given адміністратор указав назву товару, ціну 500 грн та наявну категорію
  When адміністратор зберігає товар
  Then система створює Product з указаними даними
  And пов'язує його з відповідною Category
```

## SC-05. Оновлення статусу замовлення

**Вимога:** REQ-08

```gherkin
Feature: Керування замовленнями

Scenario: Адміністратор змінює статус
  Given адміністратор вибрав Order зі статусом paid
  And новий статус processing належить дозволеному переліку
  When адміністратор підтверджує зміну статусу
  Then система зберігає processing у Order.status
```

## SC-06. Повний процес покупки

**Вимоги:** REQ-03, REQ-05, REQ-06, REQ-09

```gherkin
Feature: Повний процес покупки

Scenario: Завершена покупка
  Given покупець оформив Order з двома одиницями товару по 500 грн
  And у OrderItem.unit_price збережено 500 грн
  And платіж на 1000 грн уже ініційовано
  And платіжний сервіс надіслав підтвердження успіху
  When система обробляє результат оплати
  Then система зберігає Payment зі статусом success
  And залишає один Payment для Order
  And зберігає історичну ціну OrderItem.unit_price 500 грн
```
